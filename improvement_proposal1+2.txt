 NivelArena Simulator 종합 개선 및 리팩토링 제안서

  본 문서는 기존의 아키텍처 개선 제안과 게임 룰 구현 확장을 위한 제안을 통합하여 정리한 로드맵입니다. 프로젝트의
  유지보수성, 확장성, 그리고 게임 룰의 완벽한 구현을 목표로 합니다.

  1. 아키텍처 및 코어 시스템 (Architecture & Core Systems)

  가장 우선순위가 높습니다. 후반부 카드팩(BT05 등)의 복잡한 로직을 감당하기 위해서는 기반 시스템의 개선이 필수적입니다.

  🔴 상태 관리 및 페이즈 시스템 고도화
   * Action/Reducer 패턴 도입 (State Management):
       * 현황: GameEngine의 거대한 가변 state 객체를 직접 수정하여 추적이 어렵고, UI 갱신이 비효율적임.
       * 개선: Redux 스타일의 Action/Reducer 패턴을 도입하고 불변성(Immutability)을 적용. 상태 변경을 예측 가능하게
         만들고 디버깅(Time Travel) 용이성 확보.
   * 페이즈 매니저(Phase Manager) 및 훅(Hook) 시스템:
       * 현황: 단순 switch문으로 페이즈가 전환됨. "메인 페이즈 시작 시" 등 특정 타이밍 트리거 불가.
       * 개선: PhaseManager 클래스로 분리하고 OnEnter / OnExit 훅을 구현.
       * 목표: 이스케이프(Escape) 키워드(페이즈 시작 시 발동) 등의 자동화 로직 처리 기반 마련.

  🟡 의존성 주입 및 효과 시스템 분리
   * Effect/Condition 검증 로직 분리:
       * 현황: EffectManager 내 checkCondition이 비대해지고 있음.
       * 개선: ConditionValidator 클래스로 분리. ActionProvider를 통한 효과의 동적 등록 시스템 구축 (플러그인 구조).
       * 목표: 믹스(Mix), 성약(Covenant) 등 복잡한 조건 처리를 모듈화.
   * 엄격한 타입 체크 (Type Safety):
       * 현황: as any 단언문과 모호한 타입 존재.
       * 개선: PendingEffect, GameState 등의 인터페이스를 Union Type 등을 활용해 정교화하고 any 제거. 매직 넘버/스트링을
         constants.ts로 분리.

  2. 게임 메카닉 및 룰 확장 (Game Mechanics & Rules)

  아키텍처 개선을 바탕으로, 현재 누락된 후반부(BT02~BT05, ST08~09) 핵심 메커니즘을 구현합니다.

  🔴 핵심 누락 키워드 구현
   1. 이스케이프 (Escape) [BT05, ST08~09]: Phase.MAIN 진입 시 트리거되는 ActivationCondition.PHASE_START 로직 구현.
   2. 믹스 (Mix) [BT05, ST09]: EffectCondition에 ATTRIBUTE_VARIETY 등을 추가하여 필드 속성 다양성 검사 로직 구현.
   3. 크레딧 (Credit) [ST08~09]: 카드 로딩 시 Credit 키워드 감지 후 자동으로 Entry/Exit 효과(드로우/버리기)를 주입하는
      팩토리 로직 구현.
   4. 성약/맹세 (Covenant) [BT04]: PlayerState에 제약(constraints) 객체를 추가하여 턴 단위 제약 로직 구현.
   5. 유니크 (Unique) [BT02]: 아이템 장착 시 동명 카드 수량 제한 로직 추가.

  🟡 액션 및 타겟팅 고도화
   * 영역 조작 확장:
       * 대미지 존: MOVE_TO_DAMAGE_ZONE, PICK_FROM_DAMAGE_ZONE (회복, 자해, 교체 효과).
       * 덱/트래시: 덱 맨 아래로 되돌리기, 덱에서 특정 카드 서치(Search).
       * 스킬 존: 스킬 존의 카드를 비용으로 트래시하거나 대상으로 지정하는 기능.
   * 아이템 심화: 장착 아이템의 코스트 합 참조, 장착 해제/이동 액션 추가.

  3. UI/UX 및 프론트엔드 (Frontend Modernization)

  복잡해지는 게임 상황을 사용자에게 명확히 전달하기 위해 시각적 개선이 필요합니다.

  🔴 최신 프레임워크 도입 (React / Vue)
   * 현황: element.innerHTML 교체 방식은 성능 저하 및 상태 보존(포커스, 애니메이션)에 치명적.
   * 개선: React 또는 Vue 도입 강력 권장.
   * 이점: 컴포넌트 기반 개발로 main.ts 복잡도 해소, 효율적인 DOM 갱신, 복잡한 UI(팝업, 리스트) 구현 용이.

  🟡 상세 정보 확인 및 피드백
   * 영역 확인 UI: 덱 잔여 매수, 트래시 내용물, 대미지 존 카드를 확인할 수 있는 팝업/패널 구현 (서치 및 대미지 참조 효과
     필수).
   * 선택 모드 명시: 타겟 선택 시 출처(덱, 패, 필드, 스킬존)를 명확히 구분하는 UI.
   * 시각적 피드백: 선택 불가능한 대상 dimmed 처리, 카드 이동 애니메이션, 자동 효과 체인(Stack) 시각화.

  4. 데이터 및 테스트 (Data & Quality Assurance)

  🟡 데이터 검증 및 파싱 강화
   * JSON 파싱: 복잡한 조건이 섞인 텍스트(BT01-019 등) 처리를 위해 정규식 파싱 로직 강화 또는 데이터 구조 자체를
     구조화된 형태(Effect 객체 포함)로 마이그레이션.

  🟡 테스트 확장
   * 통합/E2E 테스트: 실제 게임 시나리오(시작~종료)를 검증하는 테스트 추가.
   * AI 봇 테스트: 랜덤 행동 봇을 이용한 대량 시뮬레이션으로 엣지 케이스 및 밸런스 검증.

  ---

  📅 통합 우선순위 로드맵 (Prioritized Roadmap)

  이 순서는 안정성 확보 -> 필수 기능 구현 -> 사용성 개선의 흐름을 따릅니다.

   1. Phase 1: 코어 리팩토링 (기반 공사)
       * any 타입 제거 및 타입 정의 강화.
       * PhaseManager 분리 및 훅 시스템 구현 (이스케이프 등 트리거 기반 마련).
       * ConditionValidator 분리.

   2. Phase 2: 핵심 메카닉 확장 (룰 완성)
       * BT04/BT05 대응을 위한 대미지 존 조작, 덱 서치 액션 구현.
       * 믹스, 크레딧, 성약 등 신규 키워드 로직 및 데이터 파싱 처리.

   3. Phase 3: UI 현대화 (프레임워크 도입)
       * React/Vue 도입하여 뷰 레이어 재작성.
       * 트래시/덱/대미지 존 확인 팝업 등 필수 UI 구현 (Phase 2 기능의 시각화).

   4. Phase 4: 고도화 (품질 향상)
       * 상태 관리(Redux 패턴) 전면 적용.
       * 통합 테스트 및 AI 시뮬레이션 도입.
       * 애니메이션 및 이펙트 추가.
