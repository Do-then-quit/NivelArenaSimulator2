# 고정 메타덱 연습용 AI 봇 착수 가이드 (2026-03-10)

## 목적

- 이 문서는 2026-03-10 기준으로 현재 저장소 상태를 다시 점검한 뒤,
  "고정 메타덱 기반의 연습 상대용 AI 봇"을 어떻게 시작할지 정리한 실행 가이드다.
- 목표는 최강 봇이 아니라, 사람이 대전 상대를 구하기 어려울 때
  심심풀이 또는 연습 상대로 충분한 수준의 플레이를 제공하는 것이다.
- 그래도 각 메타덱의 기본 전개, 핵심 콤보, 자원 보존, 킬각/블록 판단은
  납득 가능한 수준으로 보여야 한다.

## 현재 상태 스냅샷

- AI 활성 로드맵은 이미 "덱 탐색보다 고정 매치업 플레이 봇 우선"으로 재정의되어 있다.
- 엔진 진입점은 이미 고정되어 있다:
  - `getLegalActions(actorPlayerId?)`
  - `step(action)`
  - `getObservation(actorPlayerId)`
  - `getSerializableState()`
- 현재 저장소에는 `BaselineBot`, `StrongBot`, `StrongBotV2`, `StrongBotV3`가 있고,
  평가/라더/회귀/승격 게이트 스크립트도 이미 존재한다.
- 2026-03-10 기준 `npm run ai:regression` 실행 결과:
  - AI 회귀 23 파일 70 테스트 통과
  - `npm run test:bot-soak` 통과
- 현 시점의 출발 기준선은 `strong-v3`다.
  - `strong-v3`는 `strong-v2` 대비 holdout 개선 기록이 있다.
  - `strong-v3.1-topk3` 후보는 2026-02-13 승격 게이트에서 `strong-v3` 대비 성능이 후퇴했다.

## 핵심 판단

- 지금 필요한 것은 새 엔진이나 새 RL 파이프라인이 아니다.
- 가장 먼저 필요한 것은 "고정 메타덱 + 고정 매치업" 평가 레일이다.
- 현재 하네스는 명시적 `player1Deck` / `player2Deck` 주입을 지원하므로,
  엔진을 뜯지 않고도 고정 덱 매치업 평가를 붙일 수 있다.
- 반면 기본 덱 생성 흐름은 아직 seed 기반의 합법 랜덤 덱에 더 가깝다.
- 따라서 첫 구현 우선순위는 아래와 같다:
  1. 메타덱 레지스트리
  2. 고정 매치업 벤치/승격 스크립트
  3. 덱별 플레이 가이드라인이 들어간 practice bot 프로필

## 단기 목표 정의

- 덱은 소수의 메타덱으로 고정한다.
- 첫 범위는 최대 2개 덱만 잡는다.
  - `FM-A`: A 미러전
  - `FM-B`: A vs B (진영 스왑 포함)
- 평가 대상 봇은 비공개 정보를 직접 읽지 않고 관측 기반으로만 결정해야 한다.
- 성능 목표는 "최강"이 아니라 "연습 상대로 납득 가능"이다.

## 비목표

- 지금 단계에서 전 카드풀 덱 탐색을 KPI로 두지 않는다.
- 지금 단계에서 PPO/BC 학습을 먼저 붙이지 않는다.
- 지금 단계에서 메타 생성, 공진화, PSRO를 시작하지 않는다.

## 권장 구현 순서

## 1) 고정 덱/매치업 인프라

- 메타덱 2개를 먼저 확정한다.
- 각 덱 리스트를 레포에 고정 파일로 보관한다.
- seed suite와 별개로 matchup id를 명시한다.
- side-swapped 기본 평가 단위를 먼저 고정한다.
  - 예: `200 + 200`

권장 파일 방향:

- `scripts/ai/fixed_matchup/decks/`
- `scripts/ai/fixed_matchup/matchups.ts`
- `scripts/ai/run_fixed_matchup_batch.ts`
- `scripts/ai/run_fixed_matchup_promotion.ts`

중요:

- 메타덱이 현재 랜덤 deck pool 범위(`ST01`, `ST02`, `ST03`, `BT01`) 밖에 있더라도,
  카드 구현만 되어 있다면 명시적 덱 주입 경로로 우회 가능하다.
- 다만 카드 로직 미구현 상태의 카드가 섞이면 플레이 품질이 아니라
  룰 구현 자체가 먼저 병목이 된다.

## 2) 덱별 practice bot 프로필

- `strong-v3`를 베이스라인으로 사용한다.
- 새 봇은 범용 최강 봇이 아니라 덱 이해형 practice bot으로 설계한다.
- 초기에 RL보다 휴리스틱/탐색형 보강이 더 빠르다.

우선 넣을 덱별 정책:

- 멀리건 우선순위
- 초반 전개 라인 우선순위
- 핵심 콤보 파츠 보존 규칙
- 코스트 지불 우선순위
- 타겟 선택 우선순위
- optional effect 사용/스킵 기준
- 킬각 우선 공격 / 자해성 오픈 방지

권장 구조:

- `src/logic/ai/`
  - 기존 `StrongBotV3`는 공통 탐색 엔진 역할 유지
- 신규 덱별 정책 레이어 예시:
  - `src/logic/ai/practice/`
  - `src/logic/ai/practice/deckProfiles/`
  - `src/logic/ai/practice/PracticeBot.ts`

## 3) 테스트 전략

- 덱별 회귀는 일반 승률 테스트보다 "의도된 플레이가 나오느냐"를 먼저 본다.
- 각 덱마다 최소 10~20개의 시나리오 테스트를 권장한다.

우선 시나리오 예시:

- 멀리건에서 핵심 스타트 카드 유지
- 초반 2~3턴 곡선 전개
- 콤보 파츠를 비용으로 잘못 버리지 않기
- 제거 대상 우선순위
- 강제 블록 / 킬각 공격
- optional 효과를 무의미하게 남발하지 않기

필수 게이트:

- `max_steps=0`
- `no_action=0`
- `invalid_action=0`
- `npm run ai:regression`
- `npm run test:bot-soak`

## 4) 수동 검수 루프

- 숫자만으로는 "덱 이해가 느껴지는가"를 확인하기 어렵다.
- 저장된 커스텀 덱을 이용한 bot-vs-bot replay를 적극 사용한다.
- 한 덱당 최소 20게임 정도는 사람이 직접 로그/리플레이를 본다.

우선 체크할 것:

- 콤보를 언제 참는지
- 제거기를 어디에 쓰는지
- 업그레이드를 과투자하는지
- 직접 킬각을 놓치는지
- 상대 킬각에 무방비로 열어주는지

## 5) 난이도 운영

- 처음부터 일부러 약하게 만들 필요는 없다.
- 우선은 "제대로 아는 플레이"를 만드는 것이 먼저다.
- 난이도는 그 다음에 별도 프로필로 나누는 것이 좋다.

권장 난이도 분리:

- `practice-easy`
  - 탐색 폭 축소
  - 일부 합법 수 중 상위 후보 랜덤화
- `practice-normal`
  - 기본 연습 상대
  - 덱별 정책 on
- `practice-strong`
  - `strong-v3` 기반에 덱별 정책만 더한 프로필

## 권장 완료 기준

정량 목표(권장):

- `baseline` 대비 고정 매치업에서 안정적으로 우세
- 같은 덱 기준 `strong-v3` 상대로 완패하지 않음
- 안정성 게이트 0 실패

정성 목표(필수):

- 덱의 핵심 콤보/플랜을 눈에 띄게 수행
- 초보자 입장에서 "이 덱이 무슨 덱인지"가 플레이 로그로 드러남
- 억지 업그레이드, 의미 없는 코스트 지불, 자해성 오픈이 반복되지 않음

## 지금 바로 착수할 작업

1. 메타덱 2개를 고른다.
2. 그 2개를 레포 내 고정 decklist로 만든다.
3. 기존 `run_match_batch`를 감싸는 `fixed_matchup` 전용 실행기를 추가한다.
4. `strong-v3` 기반 practice bot 프로필 1개를 만든다.
5. 덱별 시나리오 테스트와 replay audit 루프를 붙인다.

## 메모

- `scripts/ai/bot_registry.ts`와 UI용 `src/logic/ai/BotRegistry.ts`는 등록 범위가 다르다.
- 새 봇 프로필을 CLI 벤치와 UI replay 양쪽에서 쓰려면 두 레지스트리를 함께 갱신해야 한다.
- 장기적으로 BC/RL을 붙일 수는 있지만,
  현재 목표와 현재 코드 상태 기준으로는 FM0/FM1을 먼저 끝내는 편이 훨씬 효율적이다.
